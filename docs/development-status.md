## 二、当前外观与布局改造方向

已经确定的设计原则：

- 不再让所有页面自由堆卡片。
- 主任务页面采用固定专业模板：
  - 设备工作区：左侧设备/连接上下文，右侧主工作区。
  - 曲线页：左侧通道控制，右侧全高曲线画布。
  - 会话页：左侧录制工作台，右侧历史会话表格。
  - 日志页：顶部筛选条，下方全高日志表格，右侧详情抽屉。
  - 设置页：左侧分类标签，右侧单分类内容。
- 关键状态、安全操作、急停状态、连接状态不能被用户隐藏。
- 空态必须说明状态、原因、下一步动作，并展示相关设备或路径。
- 长路径、设备 ID、会话名、日志正文必须有可读策略，不能只靠省略号。
- 页面框架保持稳定，滚动发生在表格、图表、日志列表等内部区域。

## 三、接下来开发规划

### Phase 3：数据页、日志页、设置页迁移（已完成）

状态：已完成，执行结果见上文 Phase 3 完成记录。

目标：把曲线、会话、日志、设置迁移到固定专业模板，彻底解决散乱卡片、大面积空白、长文本不可读和日志筛选不足问题。

推荐执行顺序：

1. 共享数据展示组件
   - 新增 `EmptyState`、`PathValue`、`StatusBadge`。
   - 统一空态、路径展示、状态徽标样式。
   - 先写测试，再实现。

2. 曲线页迁移
   - 保留现有 uPlot 实现。
   - 拆出 `ChannelSidebar` 和 `ChartToolbar`。
   - 主图表区域全高、内部自适应，不再被卡片边框挤压。

3. 会话页迁移
   - 左侧合并为录制工作台。
   - 右侧历史会话表格撑满主区域。
   - 删除会话走统一确认弹窗。
   - 空历史状态展示保存目录、当前设备和开始录制动作。

4. 日志页迁移
   - 增加四类用户筛选：`warning`、`error`、`info`、`bug`。
   - 内部 `warn` 映射为 `warning`，内部 `debug` 映射为 `bug`。
   - 建立日志详情抽屉，完整展示长日志内容。
   - 日志页采用专业检索工具布局：顶部筛选条，下方全高表格。

5. 设置页迁移
   - 改为分类标签页。
   - 分类包括：应用与路径、外观与布局、连接配置、账户与权限、日志与诊断、数据迁移。
   - 一次只显示一个分类，避免多个设置卡片并排堆叠。
   - 长路径全部使用 `PathValue`。
   - 密码重置、权限变更、迁移执行等危险操作走统一确认。

### Phase 4：性能与稳定性专项

目标：解决用户反馈的卡顿、无响应、黑窗口重启闪烁等问题。

建议任务：

1. 启动流程诊断
   - 检查 Tauri 启动日志、前端首次渲染、Rust 后端初始化顺序。
   - 确认是否有循环重启、端口冲突、代理干扰或前端热更新异常。

2. 渲染性能优化
   - 对实时表格、曲线、日志列表做渲染频率限制。
   - 避免全量 snapshot 变化导致整页重渲染。
   - 对 Three.js 场景做生命周期和资源释放检查。

3. 构建体积优化
   - 根据 Vite chunk 警告拆分大模块。
   - 优先按 Three.js、uPlot、设备工作区、设置页做动态导入。

4. 崩溃证据链
   - 增加前端 error boundary。
   - 增加 Rust 日志文件定位。
   - 增加启动失败时的诊断导出入口。

### Phase 5：协议、串口与运行时补全

目标：继续推进之前评估中尚未满完成度的核心功能。

建议任务：

1. 协议编解码
   - 完善下位机指令解析和上位机指令发送路径。
   - 增加边界值、非法帧、CRC、超时测试。

2. 串口与设备运行时
   - 完善自动扫描、手动添加、设备关闭、状态同步。
   - 增加设备断连、重连、端口占用处理。

3. 安全控制和命令队列
   - 补全命令排队、取消、超时、失败重试、审计日志。
   - 明确自动控制与手动控制的互斥规则。

4. 实时数据、表格、曲线
   - 完善实时数据采集、曲线写盘、历史回放。
   - 建立表格与曲线共享的数据窗口策略。
