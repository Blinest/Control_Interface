# SoftUI 上位机工作台布局与视觉重构设计

## 1. 目标

依据控制框图、`SoftUI_SRS_需求规格说明书.md`、`SoftUI_TDS_开发技术设计说明书.md` 和当前 React/Tauri 实现，重构上位机的信息架构、页面布局和视觉系统，使设备连接、监控、控制、录制、回放与诊断形成清晰、稳定且安全的操作路径。

本次设计重点解决以下问题：

- 自由卡片堆叠造成的对齐混乱和大面积无效空白；
- 全局导航、页面标签和操作按钮层级混杂；
- 顶部操作栏拥挤、换行和裁切；
- 页面职责不清，主任务和辅助信息视觉权重相同；
- 浅色与深色主题只切换背景，按钮、文字和禁用态对比度不稳定；
- `App.tsx` 和 `App.css` 过度集中、重复覆盖，导致修改容易回归；
- 安全状态和危险操作缺少统一、持续可见的交互规则；
- 小窗口下依赖隐藏或裁切内容，缺少可靠的响应式策略。

## 2. 已确认决策

1. 总体采用“模块化工作台”布局，不采用自由停靠式 IDE 布局。
2. 支持连接和监测多个设备，但同一时间只有一个“当前控制设备”。
3. 当前设备决定控制命令、录制、实时数据、曲线和回放的业务上下文。
4. 总览与设备工作台的“监控”标签允许自定义功能卡；其他专业页面保持固定布局。
5. 可配置卡片只允许四档尺寸：小 `1x1`、宽 `2x1`、高 `1x2`、大 `2x2`。
6. 急停按钮固定在全局顶栏，点击后立即执行，不显示确认框。
7. 急停后锁定全部运动控制；恢复必须由有权限用户确认，并由 Rust 后端重新校验。
8. 软件提供完整浅色和深色主题。首次启动跟随 Windows，用户手动选择后按用户持久化。
9. 主题必须在登录界面渲染前应用，不允许启动闪白或无原因切换背景。
10. 主题切换覆盖背景、字体、按钮、输入框、标签页、表格、图表、滚动条、状态色、禁用态、悬停态和焦点态。

## 3. 设计原则

### 3.1 任务优先

每个页面只有一个主任务。辅助信息必须服务于主任务，不能用同等级卡片抢占空间。

### 3.2 设备上下文唯一

所有设备相关页面共享同一当前设备选择。界面必须持续显示当前设备，避免用户在不同标签中对错误设备操作。

### 3.3 安全状态持续可见

当前设备、连接状态、使能状态、录制状态和急停入口不属于可隐藏卡片，始终显示在全局状态栏。

### 3.4 页面框架稳定

页面壳不依赖内容数量改变高度。表格、日志、图表和列表在自己的区域内部滚动，禁止通过 `overflow: hidden` 静默裁掉内容。

### 3.5 视觉令牌驱动

所有颜色、边框、文字层级和组件状态通过语义主题令牌定义。业务组件不直接写主题专用颜色。

### 3.6 后端最终准入

前端负责表达意图、解释风险和收集确认；Rust 继续负责权限、安全联锁、参数范围、控制互斥和命令最终准入。

## 4. 全局信息架构

应用采用四层稳定框架：

1. 左侧任务导航；
2. 顶部全局设备与安全状态栏；
3. 页面内任务标签和主工作区；
4. 底部运行状态栏。

### 4.1 左侧任务导航

导航按业务分组：

- 运行
  - 总览
  - 设备工作台
  - 曲线分析
- 数据
  - 会话与记录
  - 日志与诊断
- 系统
  - 系统设置

侧栏底部放置主题入口和当前用户菜单。刷新、连接、录制、导出等操作不放在侧栏，它们属于全局状态栏或页面局部工具栏。

标准桌面显示图标、标题和必要的辅助文本；紧凑桌面收窄为图标栏，并通过 tooltip 显示名称。

### 4.2 顶部全局状态栏

固定显示：

- 当前控制设备名称；
- 串口及连接状态；
- Ready / Enabled / EmergencyStopped 等运行状态；
- 录制状态；
- 固定红色急停按钮。

顶部栏只承载全局高频状态和安全操作。刷新、保存布局、账户操作等低频命令进入对应页面或账户菜单，避免按钮横向堆积。

### 4.3 页面内标签

设备工作台包含：

- 监控；
- 实时数据；
- 手动控制；
- 自动控制；
- 回放。

标签只切换当前业务任务，不重复全局导航。切换标签时，当前设备、连接、安全和录制上下文保持不变。

### 4.4 底部运行状态栏

底部状态栏显示：

- 采样率与界面帧率；
- 数据丢弃和协议错误摘要；
- 命令队列长度；
- 后台健康状态；
- 当前数据目录的简短表示。

完整路径通过 tooltip 或详情区查看，不能只显示无法读取的省略号。

## 5. 多设备操作模型

- 可以同时连接和监测多个设备。
- 设备工作台左侧上下文栏列出已连接设备和最近状态。
- 用户必须显式选择当前控制设备。
- 曲线、表格、控制、录制和回放默认跟随当前设备。
- 非当前设备继续接收快照和告警，但运动控制不可用。
- 切换当前设备前，如存在运行中的控制、录制或未完成命令，必须先处理冲突并给出明确提示。
- 后端命令仍必须携带并校验 `deviceId`，前端选择不是安全边界。

## 6. 页面模板

### 6.1 总览：DashboardLayout

结构为摘要条加主监控区域，允许用户自定义功能卡。

默认卡片：

- 当前设备与连接摘要；
- 采样率和帧率；
- 录制状态；
- 当前告警；
- 设备健康；
- 最近会话；
- 最近关键事件。

总览只提供状态和快速跳转，不承载完整控制表单。

### 6.2 设备工作台：WorkbenchLayout

稳定采用“设备上下文 + 任务主视图”：

- 左侧窄栏显示设备选择、连接信息、运行状态和快捷连接操作；
- 右侧主区域由监控、实时数据、手动控制、自动控制和回放标签占满；
- 监控标签支持卡片编辑；
- 控制标签使用固定表单和状态反馈，不允许自由卡片布局。

手动控制与自动控制分离，避免电机单次命令、校准、弯曲、主动控制和循环寿命参数堆在同一页面。

### 6.3 曲线分析：ChartLayout

采用“窄通道栏 + 最大化主图表”：

- 左侧选择设备、通道、原始值或过滤值；
- 顶部局部工具栏提供实时/历史、时间范围、暂停、缩放和导出；
- 主图表不被装饰卡片或无效留白挤压；
- 图例、光标读数和告警标记使用稳定尺寸，不能引起绘图区跳动。

### 6.4 会话与记录：RecorderLayout

采用“左侧录制工作台 + 右侧全高历史表格”：

- 左侧贯穿可用高度，包含录制状态、会话名称、开始/暂停/继续/停止和当前统计；
- 右侧历史会话表格填满剩余区域；
- 搜索、筛选和导出位于表格局部工具栏；
- 空态显示当前设备、保存目录、录制条件和开始录制操作。

### 6.5 日志与诊断：TableLayout

采用“过滤工具栏 + 全高日志列表 + 详情抽屉”：

- 级别筛选固定为 `warning`、`error`、`info`、`bug`；
- `bug` 映射内部 `debug` 级别；
- 支持时间、模块、设备、会话和文本筛选；
- 行内只显示可扫描摘要，完整上下文在右侧详情抽屉；
- 诊断导出属于页面局部操作，不占用全局顶栏。

### 6.6 系统设置：SettingsLayout

采用“左侧分类 + 右侧单一表单区”：

- 应用与路径；
- 外观与布局；
- 连接配置；
- 账户与权限；
- 日志与诊断；
- 数据迁移。

一次只显示一个设置分类。路径、账户表单、诊断导出和迁移不再作为多个同等级卡片并排堆放。

## 7. 可配置卡片系统

### 7.1 适用范围

只允许在以下区域使用：

- 总览；
- 设备工作台的监控标签。

实时数据、手动控制、自动控制、曲线、回放、会话、日志和设置采用固定专业布局。

### 7.2 编辑能力

进入显式“编辑布局”模式后，用户可以：

- 从允许列表添加卡片；
- 隐藏非必需卡片；
- 拖动排序；
- 选择小、宽、高、大四档尺寸；
- 预览响应式降列结果；
- 保存、取消或恢复默认布局。

正常浏览模式不显示拖动手柄，避免误拖。

### 7.3 安全限制

以下元素不属于卡片，不能隐藏或移动：

- 当前控制设备；
- 连接状态；
- 使能状态；
- 急停状态和急停按钮；
- 全局故障横幅。

### 7.4 持久化

布局按用户和页面保存，记录 schema 版本。升级时先执行布局迁移；无效或缺失卡片回退到默认布局，不阻止应用启动。

## 8. 双主题视觉系统

### 8.1 主题行为

- 首次启动跟随 Windows 系统主题；
- 用户手动切换后按用户持久化；
- 登录页渲染前读取并应用主题；
- 不对页面大面积背景执行主题切换动画；
- 切换主题不能改变组件尺寸、字重和布局。

### 8.2 语义令牌

至少定义：

- 页面背景、侧栏背景、面板背景、浮层背景；
- 主文字、次文字、弱文字和反色文字；
- 默认、弱化、强调和焦点边框；
- 主要按钮、次要按钮、危险按钮和禁用按钮；
- 输入框默认、悬停、焦点、错误和禁用状态；
- 标签页默认、悬停、选中和禁用状态；
- 表头、行、悬停行、选中行和分隔线；
- 成功、警告、错误、信息和调试语义色；
- 图表背景、网格、轴、光标和数据系列颜色；
- 滚动条轨道与滑块。

### 8.3 对比度与可读性

- 普通文字与背景对比度至少 `4.5:1`；
- 大文字、图标和关键状态图形至少 `3:1`；
- 禁用态必须显式定义背景、边框和文字色，不能只使用 `opacity`；
- 状态不得只靠颜色表达，必须同时提供文字或图标；
- 数字与时间使用等宽数字特性，普通正文使用 Windows 中文界面字体栈；
- 页面标题约 `24px`，区块标题约 `16px`，正文和控件约 `14px`，密集数据约 `13px`。

### 8.4 外观风格

- 工程软件风格安静、克制、便于扫描；
- 卡片圆角不超过 `8px`；
- 不使用渐变球、装饰光斑或营销式大标题；
- 不把页面区块设计成漂浮卡片集合；
- 图标使用 `lucide-react`，熟悉命令优先使用图标按钮并提供 tooltip。

## 9. 安全与确认交互

### 9.1 急停

- 顶栏固定红色急停按钮；
- 点击后立即向后端提交，不显示确认框；
- 后端使用最高优先级命令并清理冲突中的普通运动命令；
- UI 立即进入急停锁定表现，但最终状态以后端快照为准；
- 急停期间全部运动控件禁用并说明原因。

### 9.2 急停恢复

- 只对有权限用户显示恢复入口；
- 恢复前显示设备、当前状态和恢复条件；
- 用户确认后由 Rust 后端重新验证权限、连接状态、播放模式和安全联锁；
- 验证失败时保持急停状态，并提供关联日志 ID。

### 9.3 其他危险操作

统一确认框覆盖：

- 使能控制系统；
- 断开正在录制或运行控制的设备；
- 电机运动命令；
- 弯曲命令；
- 传感器校准；
- 启动主动控制或循环寿命控制；
- 删除会话；
- 重置密码和修改权限；
- 数据迁移与覆盖性导入。

确认框必须显示操作对象、关键参数、风险级别和即将产生的结果。确认文案由集中命令策略配置生成，禁止每个页面自行拼接不一致文案。

## 10. 错误、空态与长文本

### 10.1 错误反馈

错误采用三级反馈：

1. 操作附近的内联错误，说明当前操作为何失败；
2. 顶部非阻塞通知摘要；
3. 可展开诊断详情，包含设备、命令、错误码和日志关联 ID。

持续故障使用页面内故障横幅，不能依赖短暂 toast。

### 10.2 空态

空态必须包含：

- 当前状态；
- 形成原因或缺失条件；
- 下一步操作；
- 与任务相关的设备、路径或会话上下文。

空态区域占据主工作区的合理高度，使页面保持完整，不让一句“暂无数据”漂浮在大面积空白中。

### 10.3 长文本

- 表格单元格可以省略，但必须有 tooltip 或详情抽屉；
- 数据目录、模型目录和导出路径优先换行或使用专用路径组件；
- 日志消息在列表中省略，在详情中完整展示；
- 设备 ID、会话名和用户名不得撑破布局。

## 11. 响应式与窗口规则

主要目标是 Windows 桌面应用，不为手机触控场景优化，但必须支持较小窗口。

### 11.1 标准桌面：宽度不小于 1440

- 完整侧栏；
- 设备上下文和主工作区并列；
- 总览与监控卡片最多四列；
- 顶栏全量显示关键状态。

### 11.2 紧凑桌面：1120 至 1439

- 侧栏折叠为图标栏；
- 卡片自动降为两列或三列；
- 路径、用户名和低优先级状态收纳到详情或 tooltip；
- 表格和日志在内部水平或垂直滚动。

### 11.3 小窗口：小于 1120

- 导航变为窄图标栏或抽屉；
- 设备上下文可折叠为抽屉；
- 控制表单单列；
- 页面标签允许水平滚动；
- 急停、当前设备和安全状态仍固定可见；
- 不通过隐藏关键操作换取空间。

高度较小时，主工作区内部滚动，顶栏、页面标签和急停不离开视口。

## 12. 前端架构重构

### 12.1 目标边界

当前 `App.tsx` 约 2400 行，`App.css` 约 5700 行，并存在多次重复断点和覆盖规则。本次重构需要在迁移业务页面的同时建立清晰边界。

建议目录：

```text
src/
  app/
    App.tsx
    AppRouter.tsx
    AppShell.tsx
    navigation.ts
  components/
    layout/
      SidebarNav.tsx
      GlobalStatusBar.tsx
      PageTabs.tsx
      AppFooter.tsx
    feedback/
      ConfirmDialog.tsx
      EmptyState.tsx
      ToastRegion.tsx
      FaultBanner.tsx
    data/
      StatusBadge.tsx
      PathValue.tsx
  features/
    dashboard/
    device-workspace/
    charts/
    sessions/
    logs/
    settings/
  layouts/
    DashboardLayout.tsx
    WorkbenchLayout.tsx
    ChartLayout.tsx
    TableLayout.tsx
    SettingsLayout.tsx
  services/
    tauriClient.ts
    commandPolicy.ts
  state/
    runtimeSnapshot.ts
    themeStore.ts
    layoutStore.ts
  styles/
    tokens.css
    base.css
    shell.css
    components.css
    utilities.css
```

### 12.2 职责

- 页面组件只编排业务功能和页面模板；
- 通用组件不直接调用 Tauri `invoke`；
- `tauriClient.ts` 统一封装 IPC；
- `commandPolicy.ts` 定义操作名称、权限提示、确认级别和确认文案；
- `themeStore.ts` 负责系统主题、用户覆盖和启动前应用；
- `layoutStore.ts` 负责布局 schema、默认值、校验、迁移和持久化；
- Rust 运行时、控制状态机和协议合同在本次 UI 重构中保持兼容。

### 12.3 卡片拖动实现

使用成熟的 React 拖放方案管理排序，并由应用自己的布局模型约束四档尺寸。拖动库不拥有业务状态，保存前由 `layoutStore` 校验卡片 ID、尺寸、位置和 schema 版本。

## 13. 数据流

### 13.1 运行快照

```text
Rust device/control/session runtime
  -> batched RuntimeSnapshot
  -> runtimeSnapshot store
  -> selected-device selectors
  -> dashboard/workspace/charts/session/log views
```

页面不各自轮询同一数据。高频曲线数据继续通过专用缓冲和图表适配层处理，避免 React 频繁重建 Three.js 或 uPlot 实例。

### 13.2 命令

```text
User intent
  -> commandPolicy
  -> optional ConfirmDialog
  -> tauriClient
  -> Rust permission and safety guards
  -> command queue / transport
  -> ACK, timeout or rejection
  -> snapshot + inline feedback + logs
```

## 14. 迁移策略

采用逐层、逐页迁移：

1. 建立主题令牌、基础样式和测试基线；
2. 建立应用壳、导航、全局状态栏和底部状态栏；
3. 建立共享页面模板和反馈组件；

## 15. 测试与验收

### 15.1 自动测试

- 主题令牌完整性和禁用态规则；
- 主题初始化、系统主题和用户覆盖；
- 布局 schema 校验、迁移、恢复默认和无效数据回退；
- 当前设备切换与控制上下文一致性；
- 命令策略、确认级别和急停例外；
- 页面标签、侧栏折叠、卡片编辑和空态；
- 日志四级筛选和 `bug -> debug` 映射；
- 前端生产构建；
- Rust 安全守卫和现有运行时测试。

### 15.2 视觉回归矩阵

至少覆盖：

- 浅色与深色；
- 1600x900、1366x768、1100x700；
- 登录、总览、设备监控、实时数据、手动控制、自动控制、曲线、会话、日志和设置；
- 正常、无设备、连接中、已失能、急停、空数据、长路径、长日志和禁用态。

### 15.3 Tauri 运行验收

- 启动后主题无闪烁；
- 侧栏和标签切换不卡顿；
- 持续快照下窗口保持响应；
- 主题切换不重建高频图表或 3D 场景；
- 启停录制和浏览历史会话不阻塞界面；
- 急停立即可用，恢复严格确认；
- 小窗口无关键控件重叠、裁切或不可达；
- 运行数据仍存放在 `D:\APP\ControlUI` 指定目录体系下。

## 16. 非目标

本次布局与外观重构不包括：

- 修改 STM32 协议字段或功能码；
- 重写 Rust 控制算法；
- 替换 uPlot、Three.js 或 Tauri；
- 引入自由停靠、多窗口编排或任意像素级卡片缩放；
- 把调试终端、原始帧编辑器等高级能力默认开放给普通用户；
- 在同一阶段重做品牌标识。

## 17. 完成定义
